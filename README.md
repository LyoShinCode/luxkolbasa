колбасы с процедурной SVG-визуализацией и детерминированным неймингом.

## О задаче

Исходное техническое задание: создать одностраничное веб-приложение-конструктор
колбас с ползунками уровня соли, шпика и перца, числовыми полями, темой оформления
(светлая/тёмная), кнопкой «Создать», обработкой клавиши Enter и выводом
сгенерированной колбасы с псевдоитальянским названием.

---

## Функциональные требования

- [x] Заголовок «Мир ЛюксКолбасы» сверху экрана
- [x] Раскладка 2/3 (управление) : 1/3 (витрина)
- [x] Три слайдера (соль, шпик, перец), диапазон 0–100
- [x] Числовые поля рядом, двусторонняя синхронизация со слайдером
- [x] Кнопка «Создать» и глобальный hotkey Enter
- [x] Генерация SVG-изображения колбасы, зависящего от рецептуры
- [x] Генерация псевдоитальянского названия и характеристики
- [x] Две темы оформления с запоминанием выбора
- [x] Обработка ошибок и состояния загрузки

## Нефункциональные требования

| Категория | Реализация |
|---|---|
| **Устойчивость** | Серверная валидация, клиентская валидация, обработка сетевых ошибок |
| **Производительность** | Детерминированный PRNG (mulberry32), кэш зависимостей в Docker, многоступенчатая сборка (build + runtime) |
| **Доступность** | `aria-label`, `aria-live`, `focus-visible`, клавиатурная навигация, `prefers-color-scheme` |
| **Масштабируемость** | REST-архитектура, один метод API, разделение на статический и динамический слои |
| **Упаковка** | Полная контейнеризация через multi-stage Dockerfile |

## Архитектура

┌─────────────────────────────────────────┐
│ Браузер (SPA) │
│ HTML + CSS + Vanilla JS │
│ └── fetch('/api/generate', JSON) │
└────────────────┬────────────────────────┘
│ POST { salt, fat, pepper }
▼
┌─────────────────────────────────────────┐
│ Ktor + Netty (Kotlin 2.0, JDK 21) │
│ ┌─────────────────────────────────┐ │
│ │ static/* (index.html, css, js) │ │
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ NameGenerator (детерминированно)│ │
│ └─────────────────────────────────┘ │
└─────────────────────────────────────────┘


Почему именно Ktor, а не Spring/Flask/FastAPI:

- Kotlin как язык запроса → нативный стек;
- Ktor легковесный и идеален для маленьких проектов;
- Kotlin + Ktor — частый стек в российском финтехе (Тинькофф, Альфа) и госсекторе.

---

## Стек технологий

**Backend:**

- Kotlin 2.0.21, JDK 21 (скачивается автоматически через `foojay-resolver`)
- Ktor 3.0.3 (Netty), kotlinx.serialization
- Logback 1.4.11

**Frontend:**

- Vanilla HTML5 / CSS3 / ES6 (без фреймворков)
- Google Fonts: Playfair Display + Manrope
- Процедурная SVG-графика

**Инфраструктура:**

- Gradle 8.10 с toolchain auto-provisioning
- Docker (multi-stage build: JDK → JRE)
